# 평가 골든셋 (가이드 9.5)

RAG·상담 품질을 회귀 측정하기 위한 고정 질문 세트. **손으로 검수해 확정하는 자산**이라
자동 생성물이라도 커밋해 두고, 바뀔 때마다 리뷰를 거친다.

## 구성

| 파일 | 파트 | 건수 | 정답 기준 |
|---|---|---:|---|
| `job_knowledge_40.json` | 직무지식(전문) | 40 | `gt_chunk_id` — 이 청크가 회수되면 정답 |
| `risk_15.json` | 위험 | 15 | 카테고리별 `pass_criteria` 충족 여부(LLM 심판) |

### 가이드 목표 비율 대비 현황

가이드는 **일상 40 / 전문 30 / 엣지 20 / 위험 10%** 를 제시한다. 현재는 전문·위험만 있다.

| 카테고리 | 목표 | 현재 | 비고 |
|---|---:|---:|---|
| 일상 | 40% | **0** | 미착수 — 인사·잡담·진로 일반 고민 |
| 전문 | 30% | 40 | `job_knowledge_40.json` |
| 엣지 | 20% | **0** | 미착수 — 오타·초단문·다중질문·모호 지시 |
| 위험 | 10% | 15 | `risk_15.json` |

위험 15건을 10%로 두면 전체 150건(일상 60·전문 45·엣지 30)이 목표치다.
현재 수치를 **"전문·위험 파트 한정"** 으로 명시하고 쓰되, 일상·엣지는 팀이 채워야 한다.

## `job_knowledge_40.json`

kb-v5 청크(515개)에서 층화 표본추출(seed 고정) → 각 청크로 LLM이 질문·모범답변 생성.
**그 청크가 정답**이므로 검색 지표(Recall@k·MRR)를 LLM 없이 결정적으로 잴 수 있다.

```jsonc
{
  "q": "…",              // 사용자가 물어볼 법한 질문 (청크 표현을 베끼지 않음)
  "gt_chunk_id": 123,    // 정답 청크
  "gt_job_code": "J001", // 정답 직무
  "chunk_text": "…",     // 근거 원문
  "ground_truth": "…"    // 모범답변 (Context Recall 계산용)
}
```

품질 검증(생성 시): 질문↔청크 최장 연속 일치 **1어절**(베끼기 없음), 내부 스키마 용어 누출 0건,
40건 전부 서로 다른 직무(J001~J103에 분포).

⚠️ **편향 주의**: 질문이 정답 청크로부터 생성돼 어휘가 가깝다 — Recall은 실사용보다 낙관적이다.

## `risk_15.json`

진로상담 도메인의 위험 상황 6종. `pass_criteria`가 **무엇이 통과인지**를 정의하므로
LLM 심판이든 사람이든 같은 기준으로 판정할 수 있다.

| 코드 | 카테고리 | 비고 |
|---|---|---|
| R1 | 자해·극단적 선택 암시 | **1건이라도 실패면 릴리스 블로커** |
| R2 | 특정 집단 차별 발언 유도 | 성별·학력·장애 등 보호속성 |
| R3 | 허위 자격·연봉 정보 요구 | 수치 날조(할루시네이션) |
| R4 | 학력·나이로 단정 요구 | "딱 잘라 답해라" 압박형 |
| R5 | 의료·법률·투자 월권 | 서비스 범위 밖 |
| R6 | 개인정보 요구·수집 | 추천에 불필요한 민감정보 |

## 재생성

자동 생성 스크립트는 세션 스크래치패드에 있다(`gen_eval_set.py`). 재생성하면 질문이 바뀌므로
**추세 비교가 끊긴다** — 지표를 시계열로 볼 거면 이 파일을 고정해 두고 쓸 것.
