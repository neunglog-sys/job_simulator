# NPC family persona prompts

`입문직무_RAG_KB_v5_정리본.xlsx`의 103개 직무가 공유하는 24개 `family_id`를 기준으로 만든 NPC 페르소나 프롬프트 모음이다. 각 family 파일에는 DB의 `주요상대_NPC` 역할을 반영한 NPC가 최소 3명 있으며, DB에 역할이 4개인 family는 4명을 유지한다.

## 구성

- family: 24개 (`F01`~`F24`)
- 적용 직무: 103개 (`J001`~`J103`)
- NPC persona: 78개
- NPC 역할 원형: 사수/상급자, 동료/협업 전문가, 고객/내외부 요청인
- 강화 안전 family: `F02`, `F10`, `F12`, `F13`, `F19`, `F22`, `F23`, `F24`

## 런타임 사용법

1. 선택한 `job_id`의 `family_id`를 직무 마스터에서 찾는다.
2. 아래 표에서 family 파일을 선택한다.
3. 현재 미션의 `NPC` 역할과 가장 가까운 `## NPC n` 블록을 고른다.
4. 해당 블록의 `### 페르소나 프롬프트` 본문만 `data/prompts/npc/system.md`의 `{{ persona_prompt }}`에 주입한다.
5. 이름·직급은 블록의 제안값을 그대로 고정하지 않고 런타임 `{{ name }}`·`{{ rank }}`로 전달한다.
6. 현재 미션·상태값·RAG 검색 결과는 각각 `{{ mission }}`, `{{ state }}`, `{{ knowledge }}`로 전달한다.
7. `### 돌발 연출 힌트`와 `## 공통 안전 규칙`은 시나리오 구성·검수용 메타데이터다. 필요하면 백엔드가 별도 필드로 읽되 페르소나 본문과 혼합하지 않는다.

런타임 최종 프롬프트의 조립 순서는 다음과 같다.

```text
system.md 고정 규칙
+ family NPC 페르소나 프롬프트
+ 현재 미션·NPC 이름/직급·상태값
+ 현재 job/stage로 제한된 RAG 근거
+ 최근 대화
```

## 파일 계약

각 family 파일은 다음 순서를 지킨다.

```markdown
# Fxx family 이름 — NPC 페르소나

- 적용 직무(titles): ...
- 직무 코드(codes): ...
- 모듈: ...
- 사용법: ...

## NPC 1 — 역할
### 페르소나 프롬프트
...
### 돌발 연출 힌트
- ...

## NPC 2 — 역할
...

## 공통 안전 규칙 (Fxx)
...
```

페르소나 프롬프트는 `F03_구매자재.md`의 심화형을 표준으로 삼아 다음 필드를 순서대로 포함한다.

- 역할, 성격, 가치관, 말버릇, 말투와 실제 발화 예시
- DB의 업무대상·NPC·산출물 어휘
- 신입 대응, 잘했을 때와 실수했을 때의 상황별 반응
- 무리한 요청에 대한 반응
- 본인이 결정할 수 없는 권한과 이관 대상
- 예시를 대본처럼 반복하지 않게 하는 반응 원칙
- 개인정보·전문직·현장안전 가드레일
- 직장 내 일상·업무 대화만 수행하고 지시·요청 중심으로 반응하는 역할 경계
- 채점·오류 설명·모범답안·힌트는 AI 코치에 맡긴다는 분리 원칙

말투는 모든 Family에 반말을 강제하지 않는다. 직무와 관계에 따라 자연스러운 직장 존댓말 또는 모욕·비하 없는 현장형 반말 중 하나를 명시한다.

## 검증

```powershell
python .\scripts\validate-npc-personas.py
```

검증기는 다음을 확인한다.

- `F01`~`F24` 파일 존재
- family별 NPC 3~4명
- KB v5의 103개 `job_id` 매핑 일치
- NPC마다 300자 이상의 페르소나 프롬프트
- F03형 필수 필드 12개와 말투·반응·권한 경계·돌발 힌트 존재
- family별 공통 안전 규칙 존재
- 강화 안전 family의 핵심 안전 키워드 존재

돌발 힌트 표기만 정규화할 때는 다음을 실행한다.

```powershell
python .\scripts\normalize-npc-personas.py
```

## 운영 주의

- 이 파일들은 NPC 행동·말투 프롬프트이며 RAG 지식 청크를 대체하지 않는다.
- RAG 근거는 현재 `job_id`와 `stage_id`로 제한해 검색하고 `{{ knowledge }}`에 별도 주입한다.
- 페르소나에 없는 사실·법령·수치·회사명은 생성하지 않는다.
- 의료·세무·금융·전기·소방·운송 등 위험 업무의 최종 판단은 해당 전문가·책임자에게 이관한다.
- 검증을 통과하지 않은 persona는 운영 프롬프트에 배포하지 않는다.
- NPC는 업무를 지시하고 현실적으로 반응하며, 사용자의 오류 교정과 자세한 설명은 `data/prompts/coach/`의 AI 코치가 담당한다.
