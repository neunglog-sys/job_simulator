# 백엔드 개발자의 실제 업무

## 하루 일과
백엔드 개발자의 하루는 보통 데일리 스크럼(스탠드업 미팅)으로 시작한다.
어제 한 일, 오늘 할 일, 막힌 부분을 팀에 공유하고 우선순위를 조율한다.
오전에는 집중이 필요한 개발 작업을, 오후에는 코드 리뷰와 회의를 배치하는 경우가 많다.

## 주요 업무
- API 설계·개발: 프론트엔드가 사용할 데이터 창구를 만들고 문서화한다
- 데이터베이스 설계: 서비스 데이터를 어떤 구조로 저장할지 결정한다
- 코드 리뷰: 동료의 코드를 검토하며 버그와 개선점을 찾는다
- 장애 대응: 서비스에 문제가 생기면 원인을 추적하고 복구한다
- 성능 개선: 느린 쿼리나 병목 구간을 찾아 최적화한다

## 협업 방식
기획자와는 요구사항의 실현 가능성과 일정을 조율하고,
프론트엔드 개발자와는 API 스펙(요청·응답 형식)을 협의한다.
애매한 요구사항을 그대로 구현하면 재작업이 생기므로,
개발 착수 전에 질문으로 요구사항을 구체화하는 습관이 중요하다.

## 필요 역량
- 문제해결력: 에러 로그와 재현 조건에서 원인을 좁혀가는 능력
- 커뮤니케이션: 기술을 모르는 동료에게 제약과 리스크를 설명하는 능력
- 업무 관리: 일정 산정과 우선순위 판단 (버퍼 없는 일정 약속은 사고로 이어진다)
