# 아바타 인사말 사전 렌더 클립 — 백엔드 계약

> 대상: 아바타 담당(JMS) · 프론트 · 작성: 태수 (2026-07-20)
> 배경: 첫 발화는 사용자 입력과 무관한 고정 인사말 → 미리 렌더해 두면 **첫 발화 생성 지연이 0초**.
> "사전 렌더 SoulX 통일" 전략의 첫 적용처 (담당자 합의: 독립 진행 가능 항목).

## 아바타 담당이 할 일 — 파일 1개 배치

```
storage/avatar-clips/greeting.mp4
```

- SoulX로 렌더한 **완성 인사말 클립** (기존 완성 클립과 같은 인코딩이면 됨)
- 폴더는 서버가 기동 시 자동 생성. 파일만 넣으면 재기동 없이 바로 반영 (매 요청 시 존재 확인)
- 인사말 문구가 바뀌면 파일만 교체

## 백엔드가 해둔 것

- `/avatar-clips/*` 정적 서빙 마운트 (storage 볼륨이라 컨테이너 재빌드 불필요)
- `POST /api/consultations` 응답에 필드 추가:

```json
{ "id": 1, "status": "active", "created_at": "...", "greeting_clip_url": "/avatar-clips/greeting.mp4" }
```

- 파일이 없으면 `greeting_clip_url: null` — 기존 흐름(생성)으로 폴백, 아무것도 깨지지 않음

## 프론트가 할 일

- 세션 생성 응답의 `greeting_clip_url`이 있으면 **아바타 화면 진입 즉시 그 클립을 재생** (첫 발화를 서버 생성으로 기다리지 않음)
- `null`이면 지금 동작 그대로

## 확장 여지 (지금은 안 함)

- 필러 클립("음, 잠시만요")·자주 쓰는 리액션도 같은 폴더 규칙으로 추가 가능 — hash→클립 캐시로 발전시킬 때 이 마운트를 그대로 사용
