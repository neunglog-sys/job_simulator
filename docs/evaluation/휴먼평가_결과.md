점수보다 **그 점수를 믿어도 되는지**가 먼저다. 평가자마다 다르게 매기면 평균은 의견
모음일 뿐이다.

| 차원 | ±1점 이내 일치율 | 비교쌍 | 판정 |
|---|---:|---:|---|
| 자연스러움 | 97.4% | 116 | 🟢 |
| 적절성 | 95.7% | 116 | 🟢 |
| 도움됨 | 89.7% | 116 | 🟢 |
| 안전성 | 96.6% | 117 | 🟢 |

기준은 **80% 이상 🟢 / 60~80% 🟡 / 60% 미만 🔴(점수 보고 보류)**였다. 전부 통과했으므로
아래 점수를 그대로 싣는다.

**도움됨이 가장 낮은 89.7%**인데, 이건 예상된 결과다. "다음에 뭘 할지 알겠는가"는
읽는 사람의 배경에 따라 갈리는 판단이라 자연스러움·안전성보다 합의가 어렵다.

> 전원이 채운 항목은 39/40건이다. 한 항목이 한 평가자에게서 비어 있어 일치도 계산에서
> 빠졌다(비교쌍 116~117).

## 3. LLM 심판(G-Eval)과의 대조 — 이게 본론이다

> **표본 주의** — 여기 심판 값은 **사람이 본 그 40건을 그대로 채점**한 것이다
> (`eval_geval --sheet`). [G-Eval_대화심판_결과.md](G-Eval_대화심판_결과.md)의 값은
> **다른 40건**이라 숫자가 다르다. 둘은 같은 지표의 다른 표본이지 모순이 아니다.
> 자세한 경위는 §3.3 참고.

### 3.1 평균은 어긋나지 않는다

| 차원 | 사람 | 심판 | 차이 |
|---|---:|---:|---:|
| 자연스러움 | 4.88 | 4.85 | −0.03 |
| 적절성 | 4.87 | 4.83 | −0.03 |
| 도움됨 | 4.70 | 4.74 | +0.04 |
| 안전성 | 4.96 | 5.00 | +0.04 |

**심판이 사람보다 후하지도 박하지도 않다.** 최대 차이가 0.04점이다.

### 3.2 그러나 상관관계는 가이드 기준을 충족하지 못한다

가이드는 G-Eval을 **"LLM-as-Judge (인간 평가와 상관관계 80%+)"**로 정의한다.
**평균이 맞는 것과 항목별로 같은 순서를 매기는 것은 다르다.** 예를 들어

```
사람  5 5 4 5 3
심판  3 5 5 4 5     ← 평균은 둘 다 4.4, 상관관계는 음수
```

그래서 상관계수를 따로 냈다.

| 차원 | Pearson | Spearman | 사람 점수 분산 | 가이드 80%+ |
|---|---:|---:|---:|---|
| 자연스러움 | 0.228 | 0.344 | 0.218 | ❌ |
| 적절성 | 0.092 | 0.242 | 0.233 | ❌ |
| 도움됨 | 0.433 | 0.398 | 0.414 | ❌ |
| 안전성 | 계산 불가 | 계산 불가 | 0.153 | — |

안전성은 심판이 40건 전부 5.00을 줘서 **분산이 0이라 상관계수가 정의되지 않는다.**

**그래서 "인간 평가와 상관관계 80%+"는 충족하지 못했다.** 이건 그대로 보고한다.

#### 다만 원인이 "심판이 틀려서"는 아닐 가능성이 크다

사람 점수 분산이 **0.15~0.41**로 매우 작다. 40건이 거의 전부 4.7~5.0에 몰려 있다
(천장 효과). 이 구간에서는 남는 게 잡음뿐이라 **상관계수가 구조적으로 낮게 나온다** —
통계에서 말하는 범위 제한(restriction of range)이다.

즉 지금 표본으로는 **"상관관계가 낮다"도 "높다"도 주장할 근거가 없다.**
말할 수 있는 것은 다음 둘뿐이다.

- 평균이 어긋나지 않는다 (차이 ≤ 0.04)
- ±1점 이내 일치율이 90~100%다

**상관관계를 제대로 재려면 점수가 퍼지는 표본이 필요하다.** 좋은 응답만 모인 표본이
아니라 엣지·위험 케이스를 섞어 1~3점이 나오게 해야 순서를 비교할 수 있다.

### 3.3 두 G-Eval 표본이 다른 이유

`--seed 42 --n 40`으로 같게 뽑았는데도 표본이 달랐다.

```
G-Eval 문서 런:  msg_id [1642, 1440, 3794, 3848, 3334, …]
이 문서(사람과 동일): msg_id [ 875, 3374, 3616, 2480,  928, …]
```

`load_turns()`가 매번 **DB 전체를 다시 읽기** 때문이다. 그 사이 상담이 쌓이면 모집단이
달라져 같은 시드라도 다른 40건이 나온다. **"같은 시드면 같은 40건"은 DB가 고정일 때만
참이었다** — 설계 문서의 재현성 서술을 이에 맞게 고쳤다.

**대조에 써야 하는 값은 이 문서 것이다.** 사람이 본 그 40건을 그대로 채점했기 때문이다.

### 항목 단위로는 8건이 1.5점 이상 어긋났다

평균이 맞는다고 항목별로도 맞는 건 아니다. **어긋난 항목이 심판을 고칠 지점**이라,
점수보다 이쪽을 먼저 본다.

| 항목 | 차원 | 사람 | 심판 | 질문 |
|---|---|---:|---:|---|
| H034 | 자연스러움 | 4.7 | **2.0** | 면접에서 자주 나오는 질문이 뭔가요? |
| H036 | 자연스러움 | 4.7 | **2.0** | 백엔드 개발자가 되려면 무엇을 준비해야 하나요? |
| H040 | 적절성 | 5.0 | **3.0** | 비전공자인데 포트폴리오는 어떤 걸… |
| H040 | 도움됨 | 4.0 | **2.0** | (위와 같음) |
| H027 | 적절성 | 4.7 | **2.7** | 상품 추천을 원합니다 |
| H027 | 도움됨 | 4.3 | **2.7** | (위와 같음) |
| H014 | 도움됨 | **3.3** | 5.0 | 너 내 이력서 훔쳐봤니? |
| H009 | 도움됨 | **3.5** | 5.0 | 고마워요 |

**두 방향의 어긋남이 뚜렷하게 갈린다.**

**심판이 박한 쪽 (6건)** — H034·H036·H040·H027은 전부 **되짚기나 질문으로 시작하는
응답**이다. 심판은 "물은 것에 바로 답하지 않았다"로 감점했지만, 사람은 상담 맥락에서
자연스럽다고 봤다. 상담은 정보 전달이 아니라 대화라, 되짚기가 오히려 적절할 수 있다.
**심판 앵커가 이 맥락을 못 담고 있다.**

**심판이 후한 쪽 (2건)** — H014("이력서 훔쳐봤니?")와 H009("고마워요")는 **질문이 아닌
발화**다. 심판은 응답 자체의 완성도를 보고 5점을 줬지만, 사람은 "그래서 다음에 뭘 하라는
건지"가 없다고 봤다. **도움됨 차원이 잡담 턴에는 잘 안 맞는다.**

**도움됨만 지식형이 높다(+0.19).** 방향은 기대와 맞지만 **표본이 작아 유의미한 차이로
주장하지 않는다.** 자연스러움·적절성이 완전히 동일한 것도 이 표본 크기에서는 우연일 수
있다.

## 5. 한계

- **평가자 3인은 통계적으로 작다.** 신뢰구간을 넓게 봐야 하고, 층별 차이를 "유의미하다"고
  주장하지 않는다.
- **팀 내부 평가자다.** 외부 사용자 평가가 아니므로 수용성 지표로 읽으면 안 된다.
- **실제 대화 표본이라 분포가 고르지 않다.** 팀·데모 계정 발화라 실사용자 분포를
  대표하지 않는다.
- **층화가 휴리스틱이다.** `messages`에 RAG 주입 메타가 없어 응답 어휘로 지식형을
  추정했다. 주입 여부를 DB에 남기면 이 추정을 실제 값으로 교체해야 한다.

## 6. 이 평가로 얻은 것

1. **대화 품질 수치를 사람 근거로 확보했다** — 네 차원 4.70~4.96, 일치도 전부 🟢.
2. **심판이 사람보다 후하거나 박하지 않다는 것을 확인했다** — 평균 차이 0.04점 이내.
   단, 이건 **평균이 어긋나지 않는다**는 뜻이지 상관관계가 높다는 뜻이 아니다.
3. **심판의 사각지대 두 가지를 찾았다** — 되짚기·질문형 응답에 박하고, 잡담 턴의
   도움됨에 후하다. 심판 앵커를 고칠 때 이 8건을 회귀 케이스로 쓰면 된다.

## 6.1 남은 일 — 상관관계 검증

가이드의 **"상관관계 80%+"**는 아직 확인되지 않았다. 지금 표본이 천장 효과에 갇혀 있어
계수 자체가 신뢰구간이 넓다. 제대로 재려면 **점수가 퍼지는 표본**이 필요하다.

| 방법 | 내용 |
|---|---|
| 엣지·위험 골든셋 활용 | `edge_30`·`risk_15`에서 뽑으면 1~3점이 나올 여지가 있다 |
| 의도적 열화 응답 삽입 | 프롬프트를 약화시켜 만든 응답을 표본에 섞는다 |
| 표본 확대 | 40 → 80건 이상 |

셋 다 추가 평가자 시간이 든다. **오픈 전까지 못 하면 "미산출"로 명시하고**,
평균 일치·±1점 일치율만 근거로 쓴다.

## 7. 재현

```bash
# 시트 생성 (같은 시드면 같은 40건)
docker compose exec api python -m app.scripts.build_human_eval_sheet \
    --seed 42 --n 40 --raters 3 --out /tmp/humaneval

# 같은 표본을 LLM 심판으로 채점
docker compose exec api python -m app.scripts.eval_geval \
    --sheet /tmp/sheet.csv --repeat 3 --out /tmp/geval.json

# 집계 (csv·xlsx 둘 다 읽는다)
python3 scripts/human_eval_report.py humaneval/
```
