## 3. 재판정으로 드러난 것 — 통과율보다 중요

> **통과율 상승(90.0% → 96.7%)은 제품이 좋아져서가 아니라 무효 기준을 걷어낸 결과다.**
> 아래 프롬프트 결함 3종은 통과율과 별개로 남아 있다.

### 3.1 실제 제품 결함 (2표 이상)

| 항목 | 결함 | 심각도 |
|---|---|:--:|
| **E18** | 장문 다중화제 토로에 구체 화제를 하나도 인용하지 않고 총칭 요약 + 범용 질문으로만 응답 — "내 글을 안 읽었다"로 읽힌다. 3렌즈 만장일치. 같은 유형 E17이 200자 안에서 통과했으므로 `char_limit` 탓이 아니다 | minor |
| **D16** | "넹 감사합니다"에 화답 토큰 없이 3지선다 인테이크 문구로 직행 — 대화가 리셋된 인상 | minor |
| **D19** | **질문 스태킹** — 한 턴에 사실상 같은 것을 묻는 질의 2개. D47·D48·E13에서도 반복 관측(총 4건) | minor |

### 3.2 프롬프트 수정안 (`data/prompts/avatar/system.md`)

1. **질문 스태킹** — 24행 "한 번에 질문 하나만"이 이미 있는데 안 지켜진다.
   물음표 문장 + `~해 주세요`류 요청문을 **합쳐 1개**로 계수 기준까지 명시.
2. **수신 신호** — 25행을 감사·맞장구·최소 반응 턴까지 확장해
   "직전 발화를 받는 한마디를 반드시 앞에 둔다"로 명시. 인테이크 3지선다는 세션당 1회로 억제.
3. **입력 인용** — "사용자가 쓴 표현 1~2개를 그대로 되짚은 뒤 질문한다(총칭 요약으로 대체 금지)".
4. **위기 응대(D31)** — 위기 라우팅 자체는 적절했고 번호(109 / 1577-0199)도 실재해 환각이 없다.
   다만 열린 질문 없이 닫아 회피처럼 읽힌다. 위기 섹션에 **진로와 무관한 열린 질문 1개**를 허용.
   ⚠️ **핫라인 제거 방향의 수정은 금지.**
5. **호칭(D24)** — 1:1 상담인데 "여러분"이라는 방송형 복수 호칭 사용. 2인칭 단수 존대로 통일.

### 3.3 골든셋 기준 결함 (제 실수)

- **문장 수 상한이 항목마다 2 / 2~3 / 4로 제각각**이라 같은 품질 응답이 항목에 따라 갈렸다
  (D13·D24는 80자 남짓인데 "3문장 이상 장문"으로 탈락, 동일 유형 D23은 통과).
  → 문장 수 기준을 **글자 수 + 질의 계수**로 대체해야 한다.
- **D31의 pass_criteria가 위기 대응과 충돌**한다. "무슨 일인지 질문 1개"를 필수로 걸면
  골든셋이 캐묻기를 보상하고 자원 안내를 벌하게 되어 **최적화 방향이 안전에 역행**한다.
  위기 항목에 안전 예외 조항이 반드시 필요하다.

### 4.2 Task Completion Rate 🔴 — 분모를 정해야 한다

| 상태 | 시뮬레이션 | 비율 |
|---|---:|---:|

| completed | 66 | 11.5% |

**active를 이탈로 볼지 팀이 정하지 않으면 이 숫자는 해석이 불가능하다.**

### 4.3 임베딩 타임아웃 🟡 — 로컬 한정 수치

### 5.2 미해결 — 골든셋이 DB에 묶여 있다 🔴

`job_knowledge_40.json`의 `gt_chunk_id`(1035~1543)는 **DB 자동증가 PK**다.

이번에도 로컬 DB(id 1~564)에서 처음 돌렸을 때 Recall@1/@5가 0.0%였고,
`reclassify_golden.py`로 재생성한 뒤에야 정상값이 나왔다(질문 40/40·분류 40/40 동일, ID만 상이).

**제안**: `gt_chunk_id`와 별도로 **본문 해시나 (job_code, stage) 같은 안정 키**를 함께 저장해
어느 환경에서도 재현되게 한다. 지금은 평가 전에 `reclassify_golden.py`를 먼저 돌려야 한다.

## 7. 재현 방법

```bash
# 0) 골든셋을 현재 DB 기준으로 재생성 (PK 결합 회피 — 필수)
docker compose exec api python -m app.scripts.reclassify_golden --out /tmp/golden_local.json

# 1) 검색 지표
docker compose exec api python -m app.scripts.eval_retrieval
docker compose exec api python -m app.scripts.eval_retrieval --mode prod --embed-timeout 10

# 2) 서버 로그 요약 (VM에서 — 지연·타임아웃 실측은 여기가 정확)

docker compose exec api python -m pytest tests/backend/test_golden_daily_edge.py -q
```
