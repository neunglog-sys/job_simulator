### 5번을 왜 닫았는가 — 채점 기준이 틀렸습니다

5번의 근거는 "F 스코프로 좁혔는데도 직무 오염 35.4%"였습니다. 그 35.4%는
**정답을 청크 1개(`gt_chunk_id`)로 잡은 채점**에서 나온 값입니다.

코퍼스를 까보니 이렇습니다.

```
J 청크 515개 = 직무 103개 × 단계 5개
머리말 [직무명/직무군/유형]을 떼면 고유 본문은 120개뿐 (= 직무군 24 × 단계 5)
515개 중 490개(95.1%)가 같은 직무군 안에서 본문이 글자 단위로 동일
```

임베딩은 본문으로 거리를 잽니다. **본문이 같으면 어느 직무가 뽑히든 거리가 같습니다.**
그런데 정답을 하나만 인정하니, 글자 단위로 똑같은 근거가 검색돼도 "오염"으로 셌습니다.

정답을 **동등 청크 집합**(본문이 같은 청크 전부)으로 바꿔 다시 재면 이렇습니다.

| | 옛 채점 | 새 채점 |
|---|---:|---:|
| Recall@1 | 67.5% | **80.0%** |
| 직무 오염 (top-1) | 12.5% | **0.0%** |
| 직무군 오염 (top-1) | — | **0.0%** |

재순위화가 잡으려던 대상이 존재하지 않습니다.

### 마지막 구멍도 확인했습니다

"본문이 같으면 동등하다"에는 빈틈이 하나 있었습니다. 머리말 `[직무명/직무군/유형]`은
본문과 함께 프롬프트에 들어가므로, 본문이 같아도 머리말이 다른 직무를 가리키면
LLM이 엉뚱한 직무명을 말할 수 있습니다 — 5번이 든 "호텔리어 질문에 승무원 지식"이
정확히 이 경우입니다.

재봤습니다. 머리말 불일치 6건(15.0%)인데 **전부 질문이 직무를 특정하지 않은 문항**입니다.
직무를 콕 집어 물은 20건에서는 **불일치 0건**입니다.

```
J004 문서관리 담당      ← 머리말 J003     J028 시장조사 보조      ← 머리말 J027
J005 비품·자산관리 보조  ← 머리말 J003     J036 프로젝트관리 보조   ← 머리말 J034
J018 재고관리 사무      ← 머리말 J015     J097 통신장비 설치 보조  ← 머리말 J094
```

사용자가 직무를 묻지 않았는데 같은 직무군의 다른 직무 라벨이 붙는 건 오답이 아니고,
물었을 때는 정확히 그 직무가 나옵니다.

### 이 문서의 앞 판이 틀렸던 지점

골든셋(`298daa0`, 영수님)은 문항마다 `gt_chunk_id` 하나를 정답으로 둡니다. 코퍼스에
본문 중복이 95%라는 걸 모르면 자연스러운 설계입니다.

**제 잘못은 그 수치를 검증 없이 문서에 옮겨 "재순위화가 필요하다"는 결론까지 낸 것입니다.**
숫자를 만든 쪽이 아니라 숫자를 그대로 믿은 쪽의 문제입니다. 앞으로 이 문서에 오는
측정치는 채점 기준까지 확인하고 싣겠습니다.

## 1. `scope_chunks` — 1등만 보고 나머지를 버린다 · 완료

### 무엇이 문제였나

상담 RAG는 후보를 6개 뽑은 뒤 "이게 어느 직무 얘기인지" 판정해 좁힙니다. 그 판정이
1등 청크의 직무만 봤습니다.

```
후보: [J021, J058, J060, J058, J058, J059]
       ↑1등

정답 J058이 6개 중 3개로 최다인데,
1등이 J021이라 same=[J021] 1개 → 조건 미달 → 6개 전부 폐기
```

지식이 있는데도 한 건도 주입되지 않았습니다.

### 조치

판정을 **1등 → 최빈**으로 바꾸고, 동률은 **거리 합이 작은 쪽**으로 정했습니다
(팀 합의 2026-07-28). 후보 6개 기준 최빈=정답이 15/18이었습니다.

## 2. `max_distance` 0.35 → 0.31 · 완료

| 컷 | Recall@5 | 오프토픽 오통과 |
|---|---:|---:|
| 0.30 | 1.000 | **0%** |
| 0.35 (옛값) | 1.000 | **0%** |
| 0.40 | 1.000 | 20% |
| 0.45 | 1.000 | 75% |

컷은 **in-domain 질의에는 무력**합니다 — 상위 200청크 거리 최댓값이 0.293이라 0.30
컷조차 아무것도 못 자릅니다. 실제 역할은 **오프토픽 거절**입니다.

- in-domain 1위 max **0.267** / 오프토픽 1위 min **0.372** → 겹침 0, 안전밴드 **[0.267, 0.372]**
- 0.35는 밴드 상단 치우침(거절 여유 0.022) → 0.31이면 거절 0.062 / 회수 0.043으로 균형
- Recall 손실 0

`test_cut_stays_inside_measured_safe_band`가 밴드 경계를 고정합니다.

## 3. 임베딩 타임아웃 — 실측치를 붙입니다

현재 값은 **`RAG_EMBED_TIMEOUT_S = 1.0`** 입니다(문서 앞 판의 2.0에서 바뀌었습니다).

골든셋 40건을 순차로 돌려 왕복 지연을 쟀습니다.

| | 값 |
|---|---|
| min | 0.316s |
| p50 | **0.410s** |
| p90 | 1.302s |
| max | 10.190s |

| 컷 | 초과 비율 |
|---|---:|
| 0.8s | 17.5% |
| **1.0s (현재)** | **10.0%** |
| 1.5s | 7.5% |
| 2.0s | 7.5% |

**컷을 올려도 해결되지 않습니다.** 분포가 쌍봉이라 1.5s로 올려도 7.5%까지밖에 안 줄고
첫 토큰만 늦어집니다. 초과분은 2초를 훌쩍 넘는 꼬리라 기다려서 건질 수 있는 게 아닙니다.

고칠 방향은 **캐싱이나 재시도**이지 타임아웃 값이 아닙니다. 담당자께서 추정하신
"DB commit과 같은 이벤트 루프에서 경합"과도 어긋나지 않습니다 — p50이 0.410s로 빠른데
꼬리만 튀는 모양이라 경합 가설과 부합합니다.

주의: 위 수치는 개발 환경 측정이라 운영 값과 다를 수 있습니다.

## 4. 무근거 시 침묵 — 전제가 바뀌었습니다

앞 판의 진단은 이랬습니다.

```
임베딩 타임아웃 (3번)  ─┐
                        ├─▶ RAG 미주입 25% ─▶ 근거 없는 단정 15%
scope_chunks 오탈락(1번)─┘
```

1번이 머지되고 주입 상한도 올라가면서 **미주입률이 크게 떨어졌습니다.** 상담 실경로를
그대로 태워 잰 값입니다(임베딩 타임아웃 제외).

| 스코프 | 지식 주입됨 | 정답 근거 포함 |
|---|---:|---:|
| 추천 적중 | 100.0% | **100.0%** |
| 추천 전(전역) | 95.0% | 95.0% |

남은 미주입은 전역 검색에서 `지배 직무 없음`으로 걸러진 2건(5%)뿐입니다.
여기에 임베딩 타임아웃 10%가 별도로 얹힙니다.

**근거 없는 단정 15%를 다시 재봐야 합니다.** 원인의 상당 부분이 사라진 상태라
앞 수치는 더 이상 현재를 설명하지 못합니다.

## 5. 같은 F 내 재순위화 — 종결, 하지 않습니다

### 앞 판에 적었던 근거

| 조건 | Recall@1 | 직무군 오염 | 직무 오염 |
|---|---:|---:|---:|
| 전역 | 65.0% | 7.9% | 39.2% |
| F 스코프 | 65.0% | **0.0%** | **35.4%** |

"직무군 오염은 스코프로 0%가 됐는데 직무 오염은 거의 안 줄었다 → 같은 직무군 안
인접 직무끼리 섞인다 → 스코프 뒤에 재순위화가 필요하다"는 흐름이었습니다.

### 왜 틀렸나

35.4%는 **채점 기준 탓 허수**입니다. 상세는 위 「갱신 요약」에 적었습니다. 요약하면
같은 직무군 안 청크들이 본문이 글자 단위로 같아서, 어느 게 뽑혀도 근거가 동일한데
정답을 하나만 인정해 오염으로 셌습니다.

동등 청크를 인정하고 다시 재면 직무 오염이 **0%**입니다. 순수 검색(raw)과 상담
실경로(prod) 양쪽에서 같습니다. 머리말 직무명까지 따져도 **직무를 특정한 질문에서는
불일치 0건**입니다.

### 덧붙여 — 청크 통합과 질문 라우팅도 같이 무너집니다

전달받은 심층 분석에서 이어진 후속안 두 가지도 전제가 같습니다.

| 후속안 | 전제 | 실측 |
|---|---|---|
| J 공통 청크 → F 청크 통합 | 같은 F 안 직무 오염이 크다 | 오염 0% |
| 질문 라우팅 (F / J / 세부직업) | 스코프가 맞아도 직무를 못 고른다 | 추천 적중 시 주입·정답 100% |

특히 **청크 통합은 손해입니다.** 통합은 머리말의 직무명을 없애는 방향인데, 지금
직무를 정확히 맞히게 해주는 신호가 바로 그 머리말입니다.

## 6. (신규) 단계 오답 — `RAG_TOP_K` 3 → 5 · 완료

직무 오염이 0인데도 실패가 남아 원인을 봤더니 **단계**였습니다.

`scope_chunks`는 결과를 단일 직무로 붕괴시킵니다. 그런데 그 직무의 청크는 단계 5개
(업무요청 이해 / 자료·현황 확인 / 처리·제작·응대 / 검수·판단 / 보고·인계)로 나뉩니다.
3개만 주입하면 정답 단계가 밀려 빠집니다.

```text
J012 발주관리 담당  정답 처리·제작·응대  주입 [검수·판단, 보고·인계, 업무요청 이해]
J020 채용운영 보조  정답 검수·판단      주입 [보고·인계, 업무요청 이해, 처리·제작·응대]
```

정답 근거 포함률입니다.

| 스코프 | 주입 3 | 주입 5 |
|---|---:|---:|
| 추천 적중 | 95.0% | **100.0%** |
| 추천 전(전역) | 90.0% | 95.0% |

후보 수를 6 → 10으로 넓히는 건 양쪽 다 효과가 없었습니다. 병목은 후보가 아니라
주입 수입니다. 청크가 ~215자라 5개여도 ~1075자입니다.

**시뮬레이션 NPC의 `RAG_TOP_K = 3`은 그대로 뒀습니다.** NPC는 아는 만큼만 말해야 하고,
이 골든셋은 상담 질문으로만 이뤄져 NPC 쪽 근거가 되지 못합니다.
