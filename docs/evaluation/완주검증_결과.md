## 1. 이 지표를 무엇으로 읽었는가

가이드의 정의는 `성공 종료 세션 ÷ 전체 세션 × 100`이다. 그런데 이건 **실사용자가 있어야
의미가 있는 행동 지표**다. 우리 데이터(121세션)는 전량 팀·데모 계정의 개발 기록이고,
그중 74세션이 액션 0건이다 — 만들어만 두고 안 들어온 판이라, 비율을 내면 사용자 행동이
아니라 개발 패턴을 재게 된다.

그래서 **지금 답할 수 있는 질문으로 바꿔서** 쟀다.

> "사용자가 나갔는가"가 아니라 **"시스템이 막았는가"**

이탈은 사용자가 스스로 그만두는 것이라 사람이 있어야 하지만, **시스템이 막아서 못
나아가는 지점**은 지금도 찾을 수 있다. 그리고 이 지표가 물으려던 것도 그쪽으로 보인다.

## 2. 진행 불가 지점 검사 — 0건

`app/scripts/check_flow_blockers.py`

| 검사 | 내용 | kts-03 | sns-01 |
|---|---|---|---|
| ① 스텝 체인 | `on_pass`/`on_complete`를 따라가면 끝에 닿는가. 막다른 스텝·순환·고아 스텝 | 이상 없음 | 이상 없음 |
| ② 과제 데이터 | choice/checklist/order에 정답과 보기가 있는가 | 이상 없음 | 이상 없음 |
| ③ 미니게임 | 스텝이 부르는 `game_id`가 실제로 정의돼 있는가 | 이상 없음 | 이상 없음 |
| ④ NPC 도달성 | 걸어서 각 미션 NPC의 대화 반경까지 갈 수 있는가 | 이상 없음 | 이상 없음 |

**④가 핵심이다.** 이 게임에는 경로탐색이 없어 직선이 막히면 못 간다. 미션 NPC가 막힌
자리에 있으면 그 판은 거기서 끝나는데, 그건 사용자가 포기한 게 아니라 시스템이 막은
것이다. 프론트와 같은 판정(발박스 46×26, 대화 반경 140px, 충돌 사각형)으로 플레이어
스폰에서 flood fill 해 확인했다. NPC 자리는 게임이 쓰는 `npc_map` + `assign_spawn_slots`를
그대로 불러 배정 순서까지 일치시켰다.

## 3. 완주 경로 검증 — 8/8

`app/scripts/run_eval_sessions.py --per-map 4 --workers 4`

전용 계정(`eval-runner@jobiverse.local`)으로 새 코호트를 만들어 돌렸다. 기존 개발 기록과
섞이지 않는다.

```
kts-03   4/4 완주        sns-01   4/4 완주
채점 미통과로 중단된 판 0건
```

거친 구간: 투어 → 체크리스트·선택·배열 미션 → **서술형(LLM 채점)** → 돌발 퀘스트 →
미니게임 → 회고 → 소감문 → 완주 → 리포트.

### 완주율 100%를 지표로 쓰지 않는 이유

**본편 미션은 틀려도 완주가 막히지 않는다.** 실패하면 조언 카드가 나올 뿐 횟수 제한도
강제 종료도 없고, 돌발 퀘스트는 2회 실패하면 그냥 넘어간다. **완주를 막는 건 사용자가
나가는 것뿐인데 스크립트는 나가지 않는다.**

따라서 자동 실행의 완주율은 정답을 알든 모르든 100%다. 이탈률은 자동화로 **원리적으로**
잴 수 없다. 이 런이 증명하는 건 비율이 아니라 **"끝까지 가는 경로가 실제로 존재하고
중간에 막히지 않는다"**는 사실이다.

## 4. 이 검증이 덮지 못하는 것

정직하게 밝힌다.

| 항목 | 상태 |
|---|---|
| 프론트 조작 (걷기·클릭·대화창) | ❌ 서비스 계층을 직접 불렀으므로 안 탐 |
| 미니게임 실제 플레이 | ❌ 이 런은 완료 신호만 보냄 — **별도 기록으로 확인**(아래) |
| 이탈률 | ❌ 실사용자 필요 |
| 응답 지연 | 여기서 안 냄 — 9.4의 TTFB·채점 지연이 따로 다룸 |

미니게임이 실제로 클리어되는지는 **사람이 플레이한 기록**이 증명한다. sns-01은
`sns-01-research`·`sns-01-design` 두 게임을 통과한 완주 기록이 7건 있고(07-26~07-27),
kts-03도 미니게임 2종을 통과한 완주 기록이 있다.

## 5. 재현

```bash
docker compose exec api python -m app.scripts.check_flow_blockers
docker compose exec api python -m app.scripts.run_eval_sessions --per-map 4 --workers 4

# 실사용자가 생긴 뒤 이탈률을 잴 때
docker compose exec api python -m app.scripts.eval_task_completion --since <오픈일>
```

`eval_task_completion.py`는 실사용자 데이터가 쌓이면 그대로 돌리면 된다 — 분모를
'전체 세션 / 미션 제출 / 진입 / 끝난 판' 네 가지로 나눠 보여주고, 어느 값을 쓰든 분모를
함께 적으라고 출력에 명시한다.
